## Your job

Pick exactly ONE next action. Be aggressive about stopping — needless iterations cost real money.

- `continue` — run the next skill in `remaining_plan` as originally planned. Pick this when the prior result was unsurprising and the original plan still covers the user's intent.
- `add_skill` — drop the original plan and run a different skill next. Pick this only when the prior result reveals something the user almost certainly wants investigated by another skill (e.g. dependency-audit found a CVE in a package and the user asked broadly about "security" — security-scan now becomes worth running). Use sparingly.
- `stop` — terminate the loop and synthesize. Pick this when:
  • the user's intent is already answered by the executions so far, OR
  • we hit a hard stop (iterations cap, budget cap, or remaining_plan is empty), OR
  • running more skills would be redundant for the asked question.

## Hard constraints

- `next_skill` (when action ≠ "stop") MUST be from {lint-and-test, dependency-audit, security-scan, build-and-release}.
- `next_skill` MUST NOT be a skill already in `executed_skills` (idempotency — same repo+commit+skill is cached, not informative to re-run).
- `next_skill` MUST NOT be in the user's exclude hint: {exclude_hint}
- If `remaining_plan` is empty and you don't have a strong reason to add a new skill, you MUST pick `stop`.
- If iterations_used >= max_iterations - 1 OR cost_usd >= 0.8 * budget_cap_usd, you MUST pick `stop`.
